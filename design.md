# Storydeck design system

Locked system for every page in this app. Pages share these tokens — they do not
re-pick a palette, a font, or a card shape per route. Reference DNA extracted from
the CAVEDUCK character-discovery and character.ai feed screenshots: dark
near-black surfaces, image-first portrait cards, a persistent left nav, one accent.

## Macrostructure

```
┌────────────┬──────────────────────────────────────────────┐
│ sidebar    │ topbar: [trigger] [⌘K search] [auth actions]  │
│ 15rem      ├──────────────────────────────────────────────┤
│ (3.5rem    │ page content, max-w-7xl, px-6 py-8           │
│  collapsed)│                                              │
└────────────┴──────────────────────────────────────────────┘
```

- One shell for the whole product (`app/(app)/layout.tsx`). Auth screens are the only
  exception and live in `app/(auth)/` with a centred card and no nav.
- Sidebar is `components/ui/sidebar` (`collapsible="icon"`, `variant="inset"`), so the
  mobile drawer, keyboard shortcut and rail behaviour come from the component, not from
  hand-rolled CSS.
- Discovery pages are **section rows** (hero → tabs → chips → rows/grid), not a
  hero → features → CTA marketing rhythm.

## Colour

| token | value | use |
|---|---|---|
| `--background` | `oklch(0.145 0 0)` | page |
| `--card` | `oklch(0.185 0 0)` | raised surfaces |
| `--border` | `oklch(1 0 0 / 9%)` | hairlines only |
| `--primary` | `oklch(0.58 0.23 12)` | **the** accent: primary CTA, active nav, focus ring |
| `--muted-foreground` | `oklch(0.68 0 0)` | secondary copy |

Rules: one accent hue in the product. No gradients on text, no gradient-clipped
headlines, no violet/indigo, no glassmorphism, no coloured-left-border callouts.
Neutral surfaces carry the layout; the accent is reserved for "start / send / active".

## Type

- `--font-sans`: Geist (via `next/font`) then `Apple SD Gothic Neo` / Pretendard, so Latin
  numerals are Geist and Korean renders in the system face the references use.
- Headings roman only — never italic, never gradient-clipped.
- Display sizes: `text-3xl`/`text-4xl` for page titles, `text-sm` body, `text-xs` meta.
- Korean copy is written for humans: no "단순한 X가 아니라 Y입니다" constructions.

## Imagery

- Every character has a 2:3 portrait (`public/characters/<slug>.jpg`, generated by
  `scripts/gen-portraits.mjs`) rendered through `next/image` with `fill`, explicit
  `sizes`, and `priority` only on the first row.
- Portrait cards carry a `.card-scrim` bottom gradient so names stay legible on any art.
- No invented metrics or fake avatars: counts come from the DB (seeded demo numbers are
  labelled as mock in `scripts/seed.mjs`).

## Components

- shadcn `radix-nova` registry, all components available in `components/ui`. Use the
  component rather than re-implementing: `Card`, `Badge`, `Tabs`, `Carousel`, `Dialog`,
  `Sheet`, `Command`, `Field`, `Item`, `Empty`, `Skeleton`, `Sonner`.
- Chat uses the registry's chat set: `Message` + `MessageAvatar` + `MessageContent`,
  `Bubble` + `BubbleContent` + `BubbleGroup`, `Marker` for system lines, and
  `MessageScroller` for streaming scroll behaviour + `role="log"` announcements.
- Cards are content-first: image → name + `@creator` → one-line tagline → tags.

## Layout gates

- Responsive at 320 / 375 / 414 / 768: no horizontal scroll (`overflow-x: clip` on
  `html`/`body`), grid tracks `minmax(0,1fr)`, no two-line clickable labels.
- Portrait grid: 2 cols at 375px, 3 at `md`, 4 at `xl`; gaps `gap-4`.
- Every fetch-backed region has a `Skeleton` fallback and an `Empty` state with a next step.
- Interactive states are shadcn defaults (hover / `focus-visible` ring / disabled), never
  a hand-rolled hover colour.

## Next.js 16 conventions

- `proxy.ts` for optimistic auth redirects (middleware's new name); real checks stay in
  the page/server action via `requireSession()`.
- `cacheComponents: true` + `use cache` for the user-independent character catalog
  (`lib/characters.ts`), tagged `characters`; dynamic islands live in `<Suspense>`.
- `typedRoutes: true` — links are checked against the route tree.
- Mutations go through Server Actions (`app/actions/`), not GET side effects.
